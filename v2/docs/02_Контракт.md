# Контракт реализации v2 (0.2.0)

Статус: исследовательская реализация. Все численные примеры синтетические;
действующая нейросеть и реальные нагрузки НСКФ не испытывались.

## Входы и единицы
В JSON время задаётся в секундах: десятичные строки либо рациональные дроби.
Память — в байтах; сообщения — в битах; скорость — в бит/с. В таблицах статьи
и сводках время явно переведено в мс. 1 Мбайт = 10^6 байт.
Обязательны task_version, partition_version, infrastructure_version,
task_class и load_scope. Последнее поле — метка области нагрузки, не её доказательство.

operations: id, memory_bytes, duration_s, requires, allowed_devices.
blocks задают точное покрытие операций. Проверяются исходная ацикличность,
слабая связность и ацикличность графа частей. Неизвестный профиль не равен нулю.
devices: id, layer, memory_bytes, available, features. Кандидаты — только edge/fog.
links: id, src, dst, bandwidth_bps, latency_s, available, shared_resources.
busy: непересекающиеся полуоткрытые интервалы cpu:ID, net:ID, shared:ID.
release_s: момент готовности внешних входов блока.
deadline_s: срок в относительной шкале расчёта.
planning_delay_s + apply_delay_s: нижняя граница начала вычислений.
decision_time_s: отдельный момент проверки актуальности команды; не добавляется
автоматически к относительному расписанию. Для графа остатка начало отсчёта,
прошедшее время, сохранённые данные и оставшийся срок задаёт вызывающий код.

## Прогнозный интерфейс
kind, provenance, scale_id, direction=smaller_is_preferred, task_class,
partition_version, load_scope, issued_at_s, valid_until_s, commands.
provenance и scale_id проверяются на наличие. При заданном в задаче
expected_forecast_scale_id проверяется точное совпадение идентификатора шкалы;
при несовпадении — scale_mismatch и переход в B. Без ожидаемой метки проверка
scale_id ограничена наличием; смысл шкалы и качество источника не проверяются.
Во входах прежней серии ожидаемая метка не добавлялась задним числом.
Нет, несопоставим, просрочен, неполон или постоянен → B для всего класса.
Одно релевантное устройство → single_relevant_device, также B.
Число команды не является памятью, длительностью или вероятностью.
Горизонт не является гарантией ресурса. Метка external_neural не доказывает
существование либо обучение нейросети. Команды неизменны в течение поиска.

## P, B и D
P: (R,T,N,id), очередь по оптимистическому R; остановка лишь при строго худшей
границе всей оставшейся очереди. Минимумы команд предвычисляются один раз.
B: (T,N,id), обход по идентификаторам, без отсечения по границе времени.
D: критерий P, лексикографический обход идентификаторов, без ранней остановки
по прогнозному критерию. При неприменимости команды P и D используют B.
requested_method обозначает запрос, effective_method (и прежнее поле method)
обозначает фактический режим. forecast_status объясняет применимость/переход.
Диагностика порядка: early_stop=False и одинаковый max_checks. Это не одинаковое
время работы. При полном одинаковом множестве P и D выбирают одинаковый план.
Досрочные результаты чувствительны к разрешению равенств по ID в обоих порядках.

## Расписание и проверка
Топологический порядок: минимальный ID среди готовых блоков; сообщения — по ID
предшественника. Маршрут — по раннему прибытию; на равенстве выбирается min-ID
узла, каналы рассматриваются по ID, первая равная метка сохраняется.
Пробные резервирования изолированы. verify_plan не вызывает генератор расписания.
Память, длительности, сообщения и кандидаты он повторно выводит из model.source;
несовпадение с кэшем даёт model_aggregate:<имя>. Структурная валидация входа,
модель устройств, каналов и календарей остаются общими. Это независимость от
построителя и численных агрегатов, не независимая валидация всей физической модели.
Отсечение частичных назначений по памяти хранится в partial_rejections.joint_memory
и stats.memory_pruned; это число префиксов, а не полных планов. rejected относится
к проверенным полным назначениям. Пустой rejected при отсечении по памяти допустим.

## Повторный выбор
reconsider работает до запуска либо на явно заданном графе остатка.
Допустимое прежнее назначение по умолчанию сохраняется.
Опциональная политика allow_preference_change=True разрешает выбор при изменении
порядка, появлении или утрате применимого прогноза. Если old_forecast отсутствует,
новая применимая выдача означает forecast_became_available, а не доказанное
изменение старого порядка. Недопустимость прежнего плана вызывает обязательный
поиск без требования старого прогноза. Состав блоков не меняется.
Нет живой миграции, переразбиения, конечных очередей, банка альтернатив метода 1
и реализации реального резервирования в инфраструктуре.

## Статусы и воспроизводимость
FEASIBLE_CERTIFIED — выбор подтверждён в классе данного построителя.
FEASIBLE_LIMITED — допустимый план при неполном поиске.
NO_PLAN_IN_CLASS — в завершённо исследованном классе план не найден.
SEARCH_LIMIT_NO_PLAN — лимит без плана, не доказательство невозможности.
InputError — нарушен входной контракт, не неуспех поиска.
*_wall_seconds измеряются perf_counter (монотонные часы), не процессорным счётчиком.
Подготовка модели вне search не включена в его таймер; обучение и вызов внешней
нейросети не измерялись. Число проверок не равно полным затратам управления.
--deterministic-output исключает только изменчивые измерения времени и позволяет
побайтово воспроизвести план и счётчики. Обычные временные журналы не обязаны
повторять SHA-256. run_study сохраняет ложное matches_reference до отказа серии.
