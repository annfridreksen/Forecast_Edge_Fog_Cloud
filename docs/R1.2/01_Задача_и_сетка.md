# R1.2 — 1. Научная задача и единая сетка

22.11.2026. Раунд 1. Автор утвердила научную задачу (вариант А); техническая редакция R1.2 направляется оппоненту. Это спецификация, не выполненный эксперимент и не разрешение менять модель до утверждения проекта.

## Задача и правило минимальности
Для заданного внешнего потока найти конфигурацию Edge–Fog, одновременно удовлетворяющую p95 сквозной задержки завершённых событий ≤ 200 мс и доле потерь среди всех поступивших ≤ 0,001 (0,1%). Пороговые значения заданы автором; они не выводятся из тезисов. Не менять пороги ради непустого ответа. Результат — карта «допустимо / недопустимо / недостаточно данных» и выбор сначала минимального числа Fog, затем минимального общего для узлов буфера B. Минимальность относится только к исследуемой сетке; неопределённость у более дешёвой конфигурации запрещает объявлять найденный вариант установленным минимумом.

## Одна среда
Edge → входной канал зоны → очередь Fog → обслуживание Fog → канал Fog–Cloud → Cloud. По одному серверу Fog; FIFO без прерываний; B — места ожидания, K=B+1 включает обслуживание. Полный буфер даёт потерю; при совпадении времён сначала завершение/освобождение и продвижение очереди, затем поступление. У каждого Fog свои входной и выходной каналы; их количество изменяется вместе с Fog, поэтому исследуется конфигурация узлов с портами, не изолированная производительность процессора.

Источники: тезисы НСКФ-2026, §2, с.2–3 — 1000 Edge; совместный профиль Edge 5–15/8–20 мс; Fog 30–80 мс; Cloud 10–30 мс; исходные 8 Cloud и поток 400/ч. Допущения R1.2: **40 Cloud во всей основной сетке**, доля мобильных 0,30, доля обработки в профиле Edge 0,50, канал Fog–Cloud 20–50 мс, равномерные сервисные времена, пуассоновские внешние поступления. Исходные 1000/50/8 и 400/ч остаются контекстом предыдущей работы, не второй основной средой.

## Сетка и одинаковые входы
- Опорная нагрузка при 50 Fog: rho50 = 0,10/0,30/0,50/0,70/0,85/0,95; λ = 50·rho50/0,055 событий/с.
- При каждом **неизменном λ**: n_F = 30/40/50/60/70.
- B = **0/2/5/10/20/50/100/200/400**; малые значения добавлены как допущение, чтобы минимум буфера не задавался нижней границей прежней серии 20.
- 270 конфигураций × 10 независимых seed 0–9 = 2700 основных реализаций до адресных уточнений. Это план, не полученный результат.

При каждом λ и seed заранее сохраняются одинаковые внешние времена, идентификаторы датчиков и потенциальные сервисные времена всех стадий, включая события, которые другая конфигурация потеряет. Датчики равновероятны; закрепление за Fog: i mod n_F. Размеры зон отличаются не более чем на один датчик: для зоны j используется фактическое λ_j=λ·n_j/1000. Средняя предложенная нагрузка rho_F=rho50·50/n_F может превысить 1; конечный буфер Fog не повод удалить такие конфигурации. Устойчивость остальных, неограниченных очередей проверяется отдельно. Внутреннее время — секунды, представление задержек — мс.
