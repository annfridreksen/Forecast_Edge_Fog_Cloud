# R1.4: память, журнал и явное продолжение

23.11.2026. Это инженерный подэтап раунда 2, не изменение научной постановки.

## Реализация и проверки
`model.simulate` остаётся единственным календарём событий. `compact=True` заменяет Python-словари задач столбцами int64/float64; отсутствующие значения не равны нулю. Экспорт секунд/миллисекунд вычисляется из тех же целых тиков. `record_queue=False` не сохраняет вспомогательный рисунок очереди в больших научных сериях; первичные длительности и состояния задач сохраняются. В демонстрации прежний подробный формат остаётся по умолчанию.

Хранение O(N), а не потоковая память O(1). Ресурсный предел процесса остаётся обязательным. Предсказания/обучение не выполняются.

Локально сравнен прежний исполняемый `model.py` из b3de9c52 и новый компактный путь: 45 сочетаний (3 seed × 5 Fog × 3 буфера), по 250 сообщений; все исходные поля, целые тики, статусы, очередь и метрики совпали. AST функции начала обслуживания и переходов событий совпадает после удаления только диагностической записи очереди. Дополнительно 11 регрессий хранения проверяют ручной пример, равные времена ±1 нс, нулевые длительности, потери, окна/незавершённые и источник config_id. Это свидетельство эквивалентности хранения в указанной области, не независимое доказательство физической модели.

5 тестов реального journal writer: после прерывания на seed3 возобновление сохраняет 10 уникальных строк, а не 13; повторные чтения регистрируются отдельно, противоречивый повтор блокируется. Терминальное подтверждение не открывается повторно. Старые журналы не переписываются.

5 тестов ZIP-проверки: `verify_r14_archive.py` измеряет хеш ZIP и всех извлечённых файлов. Исходный14776143018 проверен локально: eeb0532b57ffd508c5227581864e64f01d4889e92c552b6c3296928263bd2827, 60 файлов. Старое поле отчёта `source_zip_sha256` остаётся объявленным; измеренный результат выдаёт отдельный проверяющий, и их нельзя смешивать.

## Совместимость кэша
Новая научная идентичность включает `records.py`; прежние config_id не подменяются. Импорт возможен только явно через `scripts/migrate_r14_storage.py`, с закреплёнными хешами прежней и новой версии, той же сеткой, параметрами/seed/окнами. Импортируются только первичные пилотные наблюдения и сохраняется цепочка старого/нового хеша. Научные решения, main и confirmation не импортируются. Источник и назначение — разные каталоги. Повторный импорт проверяет уже записанное и не вызывает имитацию. Семь тестов проверяют повтор, повреждение, смену кода и запрет переноса подтверждений. Фактически перенесены 43 прежних наблюдения; после прерывания импорта успешно использованы 24 уже записанных файла, новых имитаций при переносе — 0.

Максимальный защитный хвост учтён: только G=1000 дал бы2450000, а не полный верхний размер3200000.

Следующий научный пакет ограничивается900с и1100000 ожидаемых событий одной реализации, то есть ниже испытанного размера. W/T/G,10 seed и статистические пороги не меняются. Процесс всё равно имеет6GiB; ошибка ресурсов оставляет клетку нерассчитанной. Этот опыт не гарантирует безопасность всех сочетаний или память полного bootstrap/контроллера. Увеличивать предел без фиксации результата запрещено.

## Команды
После получения точного архива14776143018:
```sh
python scripts/verify_r14_archive.py --archive checkpoint.zip --root old-checkpoint --expected-sha256 eeb0532b57ffd508c5227581864e64f01d4889e92c552b6c3296928263bd2827 --artifact-id 14776143018 --output verified-archive.json
python scripts/migrate_r14_storage.py --source old-checkpoint --target new-checkpoint
OPENBLAS_NUM_THREADS=1 python scripts/run_r14_grid.py --out new-checkpoint --wall-seconds 900 --max-expected-events 1100000
```
Повторять последний запуск только после проверки отсутствия активного писателя и восстановления САМОГО НОВОГО накопленного checkpoint. CLI `run_r14_grid.py` сам по себе не устанавливает RLIMIT_AS; адресный Actions `run_r14_night.py` устанавливает его. Отдельная инженерная команда — `scripts/probe_r14_compact.py`; она не принимает научную конфигурацию.
