ЧАСТЬ 1. МОДЕЛЬ СРЕДЫ (главная), пакет efc/
Дискретно-событийная модель на Python (SimPy или своя очередь событий;
numpy, pandas, matplotlib, networkx — всё доступно в бесплатном Colab).
Параметры по умолчанию — из тезисов:
- Edge: 1000 датчиков ESP32; стационарные 5–15 мс, мобильные 8–20 мс
  (обработка + передача); канал LoRaWAN/NB-IoT.
- Fog: 50 узлов Raspberry Pi 4, обработка 30–80 мс, буфер до 400 задач,
  одна очередь FIFO на узел, переполнение → потеря задачи (считать).
- Cloud: 8 серверов, 10–30 мс; канал HTTPS/MQTT.
- Нагрузка: мониторинг парковки ≥ 1000 мест, пик 400 событий/ч,
  ~2000 транзакций/сутки; требование обновления ≤ 3 с; 200 задач в базовом
  прогоне; фиксированный seed = 42.
- Задержка задачи = 6 составляющих: обработка Edge + передача Edge→Fog +
  ожидание в очереди Fog + обработка Fog + передача Fog→Cloud + обработка
  Cloud. Каждую хранить отдельно.
- Метрики: средняя, 95-й перцентиль, максимум, среднее ожидание в очереди
  Fog, переполнения буфера, вклад уровней (%), загрузка каналов.
Короткие серии (как в тезисах): базовая 1000/50/8; датчиков +25…+100 %;
облако ×2 и ×3; Fog +50 %; буфер 20/50/100/200/400; стационарные против
мобильных; датчиков на Fog-узел 10…40.
Ориентиры тезисов (ожидается тот же порядок величин, точного совпадения
не требуется, т.к. это новая модель): 134,70 / 170,90 / 186,00 мс,
ожидание 55,73 мс; доли Edge/Fog/Cloud 16,6 / 69,1 / 14,4 %; облако ×2, ×3
метрики не меняет; оптимум 20–25 датчиков на узел, буфер 50–100.
Ориентиры тезисов нужны только как здравый смысл (тот же порядок величин);
сверку со старым кодом не делать. Если порядок величин сильно отличается —
одна строка объяснения в РЕШЕНИЯ.md, без подгонки.
Если в тезисах параметр не задан (например, пропускная способность канала,
закон потока), выбрать разумное значение, записать в РЕШЕНИЯ.md и в таблицу
параметров статьи с пометкой «допущение модели».

- Оценка: MAE для mean, доля попаданий ниже прогноза p95 (покрытие),
