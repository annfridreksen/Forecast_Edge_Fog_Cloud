## 2. Одна среда и происхождение параметров

Путь созданного сообщения: **Edge → канал Edge–Fog → очередь Fog → обслуживание Fog → канал Fog–Cloud → Cloud**. Отдельные ресурсы Edge, FIFO каждого Fog и его входного/выходного каналов; общий пул Cloud. Обслуживание без прерывания. B означает места ожидания, вместимость с обслуживаемым сообщением K=B+1. При заполнении Fog сообщение отклоняется, не получает фиктивного результата. При одинаковом времени сначала завершается обслуживание и продвигается очередь, затем обрабатывается поступление; равноприоритетные события упорядочиваются стабильными идентификаторами. Другие очереди не ограничены; их устойчивость проверяется отдельно. Увеличение числа Fog одновременно увеличивает число их портов — это конфигурационный эффект, не изолированное ускорение процессора.

**Т** — параметры предоставленных тезисов НСКФ-2026, §2, с.2–3; **Д** — синтетические допущения. Ни Т, ни Д не объявляются измерениями оборудования.

| Параметр | Значение и происхождение |
|---|---|
| Edge | 1000 — Т; доля мобильных 0,30 — Д |
| Совместный сервис Edge и передачи | 5–15 мс для стационарных, 8–20 мс для мобильных — Т; доля обработки 0,50 — Д |
| Fog / Cloud: обслуживание | 30–80 / 10–30 мс — Т |
| Cloud основной сетки | 40 — Д; прежние 8 серверов и 400 событий/ч остаются контекстом НСКФ, не второй основной средой |
| Канал Fog–Cloud | 20–50 мс — Д |
| Распределения | Пуассоновские внешние поступления, равномерные сервисные времена — Д |
| Fog / буфер | Значения сетки §3; предел 400 в тезисах — Т, трактовка B и расширение сетки — Д |

Внешние значения времени задаются в секундах, таблицы задержек — в миллисекундах. **Допущение приёмки R1.4:** новая реализация использует целочисленные тики 1 нс; исходные моменты/длительности нормализуются один раз, округлением к ближайшему тику с равенством к чётному. Десятичные входы разбираются как десятичные значения. Дальнейшие суммы, сравнения и порядок событий — целочисленные, без произвольного epsilon. Интервалы занятости полуоткрытые. Разрешение и правило округления сохраняются в метаданных; это модель с заданным разрешением, а не обещание абсолютной физической точности. Влияние смены представления учитывается при решении, какие старые результаты можно переиспользовать.

## 3. Единая сетка и одинаковые входы

Опорная нагрузка rho50=0,10/0,30/0,50/0,70/0,85/0,95; для каждого значения общий поток **λ=50·rho50/0,055 событий/с**. При неизменном λ: **n_F=30/40/50/60/70**, **B=0/2/5/10/20/50/100/200/400**. Всего 270 конфигураций × 10 итоговых seed 0–9, до пилотных и подтверждающих опытов. Это план, не выполненная серия.

Для каждого λ/seed внешний поток, event_id, ID датчиков, типы и потенциальные сервисные длительности всех стадий создаются **до выбора конфигурации**, включая сообщения, теряемые в одном из вариантов. При смене n_F/B изменяются только конфигурация, привязка и вызванное ими исполнение. Датчики равновероятны; привязка i mod n_F; λ_j=λ·n_j/1000 учитывает фактический размер зоны. Средняя предложенная нагрузка rho_F=rho50·50/n_F может превышать 1: конечный буфер Fog не основание удалить такой режим. Предложенная нагрузка и измеренная занятость — разные показатели.

Одна модель служит ручному контролю, интерфейсу и сериям; отдельный упрощённый симулятор для красивой демонстрации не создаётся. Старые CSV переиспользуются только при совпадении модели, входов, параметров и окон; отсутствие совпадения фиксируется, результаты не смешиваются. Режим 80/4/8 и обучение старого событийного MLP не входят в новую серию.

## 4. Наблюдение, неопределённость и выбор

Когорта — все созданные внешние сообщения фиксированного измерительного окна. D — время от создания до окончания Cloud; Q — p95 D условно по завершённым; L — потери/все поступления когорты. Потерянному сообщению не присваивается нулевая задержка. Незавершённые учитываются отдельно; итоговый Q не принимается до выяснения судьбы принятых сообщений.

**H(t)=число сообщений когорты, завершённых с D≤t / все поступления когорты**; t — задержка после собственного поступления. Потери остаются в знаменателе; после дообслуживания предел H равен 1−L. Показываются H(t) и H(200 мс). Они дополняют, но не заменяют отдельную совместную проверку Q и L. Средняя, максимум, ожидание Fog, загрузка и доли стадий — дополнительные показатели.

Шесть неперекрывающихся составляющих: Edge; Edge–Fog; ожидание Fog; обработка Fog; Fog–Cloud; Cloud. Каждое ожидание ресурса учитывается ровно один раз. При группировке по трём уровням каналы относятся отправителю. Доли рассчитываются для одной совокупности завершённых; сумма до округления — 100%.

Сохраняется принятый протокол прогрева:
- начальные W=2000·50/λ, T=4000·50/λ, G=1000·50/λ секунд, одинаковые при данном λ; вместо опорных 50 фактическое n_F не подставляется;
- поток продолжается в защитном хвосте; неполная когорта не объявляется окончательным результатом, хвост продлевается с явной записью;
- пилотные seed 100–109 отделены от итоговых 0–9 и подтверждающих 200–209;
- допуски ε_Q=10 мс и ε_L=0,00005 доли (0,005 процентного пункта); они не добавляются к порогам допустимости;
- сравниваются W и 2W, а также половины окна; весь ДИ разности должен лежать внутри ±ε, одного попадания нуля недостаточно;
- лестницы прогрева 2000→4000→8000→16000 и измерения 4000→8000→16000→32000 ожидаемых поступлений на опорный Fog; принимается более длинный из эквивалентных прогревов. При недостаточности эквивалентности увеличивается прогрев, точности — окно; при пределе остаётся «недостаточно данных»;
- окна фиксируются по пилоту до итоговой серии; итоговые ДИ не просматриваются повторно до удобного ответа. Уточняются затронутые режимы; парные разности требуют общего интервала.

Q и L оцениваются по объединённой когорте итоговых реализаций с сохранением данных каждого seed. Приближённый кластерный bootstrap пересэмплирует целые seed, не независимые сообщения очереди: 10000 повторов, фиксированный seed в метаданных. Описательные ДИ — 95%; половина ширины не более ε. Для совместного принятия клетки используются односторонние верхние 97,5%-е границы каждой метрики: U_Q≤200 мс **и** U_L≤0,001. Нижняя граница выше хотя бы одного порога даёт метку недопустимости; иначе — недостаточно данных. Это номинальные приближённые интервалы, не точная гарантия и не одновременное покрытие карты. Нулевые потери с вырожденным [0,0] не удостоверяют риск: без обоснованной невырожденной верхней оценки клетка остаётся неопределённой по потерям. Неопределённость не равна недопустимости.

Выбор — лексикографический минимум (n_F,B) среди оценённых допустимыми клеток. Таблица всех меньших пар содержит оценки, границы и причины исключения/неопределённости. Даже при отсутствии меньших неопределённых клеток статистическая минимальность не заявляется. Пустая область означает «кандидат по оценённой карте не найден».

Не более одного кандидата на поток фиксируется до открытия независимых seed 200–209. Успех подтверждает только этого кандидата в рамках протокола. При провале или недостаточности данных — остановка для данного λ, без подбора следующего на тех же данных. Семейная гарантия всех шести подтверждений не заявляется. Отложенное сравнение MLP/kNN/формулы сейчас не выполняется; прежнее разбиение 27/9/9 остаётся заготовкой следующего этапа, не частью текущих результатов.

## 6. Понятный Colab и ручное отключение

Главный экран: одна схема «датчики → Fog → облако»; три подписанных регулятора **внешний поток λ (событий/с), число Fog, B (мест ожидания)**; кнопка «Рассчитать и проверить». Рядом видны выбранные значения и метка режима. Остальные параметры, seed, окна и версия доступны в «Дополнительно»; без скрытого переключения с постоянного потока на поток, зависящий от числа устройств.

После расчёта — одна карточка **p95 ≤ 200 мс И потери ≤ 0,1%**, оба ДИ, H(200 мс), учёт незавершённых и статус «допустима / недопустима / недостаточно данных»; затем карта n_F×B при выбранном λ и график очереди. Отсутствующий результат обозначается «не рассчитано», не нулём. Единичный демонстрационный прогон не даёт статистического подтверждения карты. «Загружен сохранённый результат» и «сейчас выполнен расчёт» различаются с указанием источника/версии; длинная серия не запускается незаметно при перемещении регулятора.

**Условная демонстрация «Отключить датчик»** отделена от основной карты. Отключение — ручное состояние, не обнаружение неисправности и не оценка вероятности. После команды новые сообщения этого датчика не создаются; уже созданные продолжают исполняться/учитываться. При совпадении времени команда отключения предшествует генерации нового сообщения — явное правило иллюстрации. Потенциальные не созданные сообщения не включаются в знаменатель потерь Fog; основной эксперимент выполняется с исправными датчиками. Статусы визуально различимы: «обработано», «ожидает», «потеряно в Fog», «датчик отключён». Сохранённая карта не выдаётся за карту среды после такого изменения. Отсутствие сообщения само по себе не диагностирует отказ.

Обязательные подробности: временная диаграмма ручных задач; p95 и потери с ДИ от rho50; H(t); шесть составляющих и уровни; таблица происхождения чисел. 00 — вход и проверки, 01 — работающая среда/конфигурации, 02 — только концептуальные интерфейсы, 03 — концептуальная схема переразмещения. Исторические веса и выходы старого 02 не выдаются за новую реализацию. Тетради должны запускаться сверху вниз после утверждения реализации; новый запуск не заявляется по наличию старых outputs. Полные журналы и код сохраняются, но не загромождают первый экран.

## 7. Концептуальные порты и самостоятельный раздел переразмещения

«Розетка» — описанный сменный интерфейс будущего оценивателя. Сейчас каждый порт имеет статус **«не обучен / не выполняется»**, отсутствующие данные — отдельную пометку; числовые выходы отсутствуют, не равны нулю. Модельные Q/L текущего расчёта не подписываются как предсказания.

| Будущий порт | Необходимые входы / смысл выхода | Сейчас |
|---|---|---|
| Оценка p95/потерь конфигурации | λ,n_F,B и версия профилей → p95 в мс, доля потерь, область применимости | Только контракт; MLP, kNN, M/M/1/K — возможные реализации, сравнение не выполнено |
| Риск переполнения | Наблюдаемая очередь/нагрузка и отдельно заданный горизонт/событие → оценка риска | Только схема; горизонт и калибровка не подтверждены |
| Риск отказа датчика | Телеметрия, heartbeat, размеченные отказы, горизонт → оценка риска | Нет подтверждённых данных, не обучен; ручное отключение не является прогнозом |

Прогноз p95 конфигурации не даёт автоматически сопоставимых команд для целых подграфов. Связь требует отдельного адаптера, области применимости и проверки; в текущем этапе её исполнение отсутствует. Задержка, доля потерь и безразмерная порядковая команда не подменяют друг друга.

**Раздел 6 статьи: «Концептуальная схема применения метода переразмещения с учётом прогноза».** Сохранить самостоятельный раздел, а не только приложение: состояние среды → будущий прогноз → проверка применимости порядковых команд → выбор назначения целых подграфов → проверка полного плана → допустимый план либо отсутствие найденного допустимого плана. Разбиение фиксировано; состав целых подграфов сохраняется. Критерий (R,T,N,id) не меняется: R — отсортированный по убыванию вектор команд, лексикографически меньшее предпочтительно; затем расчётное время T, число переназначений N и идентификатор. Cloud присутствует в среде, но не входит в кандидаты этого метода. Предпочтение не заменяет обязательные ограничения. Переназначение не равно изменению числа Fog или переразбиению; ограниченный неуспех поиска не доказывает невозможности. Прогнозы и управляющее применение плана сейчас не выполняются; «до/после» — условная схема без вымышленных чисел и ускорения. Эталон v2/ — отдельный прежний результат, не доказательство новой интеграции. Прогнозная разгрузка Fog→Cloud — дальнейшая работа.

## 8. Статья, проверки и правила работы

План PSTA, семь разделов: **1)** введение и задача конфигурирования, НСКФ как предыдущая работа; **2)** модель среды, источники параметров, время/метрики; **3)** сетка и статистический протокол; **4)** рассчитанная карта конфигураций и границы выбора; **5)** интерфейсы будущего прогнозирования без эксперимента точности; **6)** самостоятельная концептуальная схема переразмещения (§7); **7)** заключение и ограничения.

После утверждения: русская/английская аннотации одинакового смысла, схемы/таблицы с номерами и ссылками, LaTeX/PDF PSTA. В численных результатах — только новая модель с первичными источниками; не подгонять под прежние числа НСКФ. Тезисы указать в литературе без выдуманных реквизитов. Сохранить ранее согласованную проверку реальных источников, DOI Wei 2020 и трёх R19, репозиторий/SHA; литература не доказывает выполненного прогноза. Не добавлять неподтверждённых авторов, измерений и преимуществ. Разделы 5–6 нельзя назвать экспериментально проверенной замкнутой системой. PDF/числа/подписи проверяются отдельно; статья не объявляется готовой к подаче по одному техническому PASS.

Только исполнитель коммитит в **night/fefc-v3, PR #2**; main, v2/, docs/Журнал_проверок_Perplexity.md неприкосновенны, без force-push и слияния. Один предмет исправления — один коммит с номером Issue/пункта. Экономия: читать изменения, повторять расчёты/сборку только при влияющих правках; кэш помечать точной версией, изменённую модель не подтверждать старым кэшем. STATUS — краткая карточка и грубая оценка токенов, не биллинг. «Написано», «запущено» и «принято рецензентом» разделять.

Раунд 1 — единый проект и авторское утверждение. Раунд 2 — реализация, исправление Actions/времени, журналы тестов и результаты. Раунд 3 — статья, схема/снимок начального экрана, выполненные тетради и сверка чисел. На возражения — решение с SHA или обоснованный отказ. Итоговое согласие обоих относится к точному SHA/комплекту; окончательное решение — автор. До утверждения конкретной редакции этот план не запускается.
