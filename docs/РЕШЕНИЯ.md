# Решения v3

22.11.2026. Основание: TASK.md и согласование Issue #1/7070981671. Все новые данные синтетические.

D01. Реализованы все Fog-узлы: отдельная FIFO и один обслуживающий исполнитель на узел; датчик i относится к зоне i % n_fog. Буфер B — число ожидающих, полная вместимость K=B+1; при заполнении drop-tail. Завершение обслуживания имеет приоритет над поступлением при равных временах.
D02. 400 событий/ч — суммарная интенсивность, не интенсивность каждого датчика. Поступления пуассоновские (допущение); остановка генерации после 200 событий, затем дренирование. 2000/сутки — контекст прежней работы, не одновременное требование постоянной интенсивности. Окно наблюдения и дренирование сохраняются отдельно.
D03. Интервал Edge 5–15/8–20 мс трактуется как обработка плюс передача, как в TASK; равномерное распределение и деление 50/50 — допущения. Fog 30–80 и Cloud 10–30 мс — равномерные синтетические профили. Fog→Cloud 20–50 мс — отдельное допущение, не новое измерение тезисов.
D04. На каждом датчике, uplink зоны и Fog→Cloud канале последовательное обслуживание. Сетевые сервисные времена включают ожидание канала; это не эмуляция физического протокола LoRaWAN/NB-IoT/MQTT. Cloud выбирает первый свободный из n_cloud; ожидание Cloud учитывается внутри шестой компоненты и отдельно в cloud_wait_ms. Аналогично ожидание Edge включено в первую компоненту. Поэтому сумма шести компонентов полна, без скрытых очередей.
D05. Типы, поступления, зоны, датчики и длительности используют раздельные детерминированные генераторы; изменение числа Cloud не меняет выбранные длительности. Явный trace поступлений позволяет парные проверки.
D06. Базовый запуск seed42: 200 завершений, 0 потерь, средняя 120.76746082981089 мс, p95 150.73138734382496 мс, максимум 162.66327171535977 мс, Fog-ожидание 0. При общей нагрузке 400/ч на 50 Fog нулевая очередь закономерна; 55.73 мс из тезисов не подставляется. Это новый расчёт, без сверки старого кода и без подгонки.
D07. Прямой git clone в текущем окружении недоступен (DNS github.com). Запись производится через GitHub Git Data API с проверкой SHA; не выдавать это за чистый clone. Способ final-check будет отражён по факту.
