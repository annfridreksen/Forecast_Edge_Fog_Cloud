# Issue #4, пункты 1–3: новая диагностика конфигурации

Прежний baseline 1000/50/8 и 400 событий/ч сохранён. Новая серия: 50 отдельных Fog, offered rho=0.10/0.30/0.50/0.70/0.85/0.95; 10 независимых seed; 18 сценариев (интенсивность, датчиков/Fog, буфер). Cloud=40 только в этой диагностике: при максимуме его offered rho=0.432; прежние 8 серверов при таком суммарном потоке были бы неустойчивы.

Прогрев: 2000 ожидаемых поступлений на Fog; измерение: 4000; защитный хвост: 1000. Времена окон равны этим числам, делённым на интенсивность одного Fog. Метрики задержки относятся к внешним поступлениям окна; справа они не обрезаются, завершение до конца хвоста проверяется. Загрузка ресурсов интегрируется только по окну, не по дренированию. Это постоянный поток после прогрева, а не математическое доказательство точной стационарности: сохранены первая/вторая половины и контроль удвоенного прогрева при rho=.95.

95% ДИ: Student t по независимым оценкам десяти seed, не по зависимым событиям очереди. ДИ p95 — для среднего эмпирического p95 прогона. ДИ максимума — для среднего максимума конечного окна, не границы распределения. Интервалы маргинальны. Нулевые наблюдаемые потери не гарантируют нулевого риска.

Компактная обработка ациклических стадий в порядке фактических поступлений сохраняет конечную FIFO каждого Fog. Аналитическая M/M/1/K предполагает экспоненциальный сервис, в модели сервис равномерный; совпадение кривых не ожидается.

Прежние 2000 событий при 1200/с — переходный пик. Их выводы не называются стационарными. Программа: efc/stationary.py, вызов stationary_series(); первичные строки: stationary_replicates.csv; оценки и ДИ: stationary_summary.csv; диагностика прогрева: stationary_metadata.json и warmup_replicates.csv.
