# R1.4 — контрольные точки и единый реестр кандидатов

23.11.2026. Ночное поручение #5/7086202703, замечания #5/7086444894, п.2–3.
Это механизм исполнения прежнего TASK §4; критерии, интервалы, окна и ядро не заменены.

- `CachedSampler` оборачивает `KernelSampler`. Полные и половинные когорты сохраняются как сжатый JSON с SHA-256, идентичностью модели/профилей/seed/W/T/G. Чтение проверяет хеш и баланс. Потерянные/незавершённые остаются в счётчиках; задержки завершённых — целые тики.
- Прерванный пилот воспроизводит детерминированные переходы контроллера, но завершённые имитационные реализации читает с диска, не запускает повторно. Прежний частичный журнал сохраняется в history. Из-за незавершённого математического перехода bootstrap может быть повторён; это не новый модельный опыт.
- `run_frozen(..., resume=True)` продолжает тот же журнал и тот же замороженный план. Иная фаза/конфигурация запрещена. Терминальное решение возвращается без повторной проверки. Прежний вызов без resume по-прежнему отклоняет существующий журнал.
- Linux/Colab/Actions: неблокирующая файловая блокировка не допускает второго писателя. В Actions научный workflow должен иметь отдельную concurrency group с cancel-in-progress:false; исправный процесс не отменяется новым коммитом.
- Все клетки каталога должны получить итог протокола до общей фиксации кандидатов. Для каждого потока — одна минимальная пара среди ACCEPTABLE, таблица меньших клеток. Все шесть решений сохраняются до открытия 200–209. При неудаче подтверждения другого кандидата не выбираем.
- «NOT_CALCULATED/PAUSED/FAILED» — не научная недопустимость. Отдельно считаются разрешённые протоколом клетки, клетки с десятью итоговыми seed и реальные сохранённые реализации. Провал пилота не считается десятью выполненными итоговыми seed.
- Лимит wall-seconds действует между реализациями, не прерывает текущую. Потолок ожидаемых событий — инженерная защита памяти, НЕ уменьшение окон; затронутая клетка остаётся нерассчитанной. Малый ресурсный замер не экстраполируется в гарантированное время полной сетки.
- Старые результаты не переиспользуются без совпадения scientific manifest. Нет pickle/исполняемых файлов в кэше. Manifest исключает только seed/n_tasks так же, как исходный KernelSampler; scientific source hashes сохранены.

Команды из корня репозитория:
```
python scripts/check_r14_grid.py
python scripts/run_r14_grid.py --out results/r14/grid --wall-seconds 1200 --max-expected-events 1000000
```
Вторая команда является также командой продолжения; старые совместимые наблюдения читаются с диска. `--confirm` разрешает независимую проверку только после полного разрешения каталога и неизменной глобальной фиксации. Статистическая минимальность не утверждается.

Основные файлы результата: manifest.json, map.json, progress.json; cells/<ключ>/pilot.json, main.json, confirmation.json; observations/<config_id>/*.json.gz; candidates.json и frozen-map.json.
Контрольные примеры tests/test_grid.py и validation/02_R14_resume.ipynb — синтетические маленькие примеры механизма, НЕ карта 270×10.
