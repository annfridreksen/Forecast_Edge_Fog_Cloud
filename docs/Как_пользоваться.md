# Как пользоваться FEFC v3

Рабочая ветка: `night/fefc-v3`. В `main` находится исходная база; `v2/` не менять.
Результаты уже сохранены — сначала их можно посмотреть без запуска программы.

## Посмотреть готовое
Откройте репозиторий `annfridreksen/Forecast_Edge_Fog_Cloud`, выберите ветку
`night/fefc-v3`. Статья: `article/main.pdf`. Тетради с выводами: `colab/`.
Краткое объяснение: `Модель_простыми_словами.md`. Что выполнено и что нет —
`Отчёт_ночи.md`, фактический вывод проверки — `results/final-check.txt`.

## Запустить в Google Colab
1. Откройте Colab → «Открыть блокнот» → GitHub. Укажите адрес репозитория,
   выберите ветку `night/fefc-v3` и `colab/clean/00_Старт.ipynb`.
2. Выберите «Среда выполнения → Выполнить всё». Первая тетрадь получает проект,
   устанавливает зависимости и запускает тесты. Успешный вывод заканчивается OK.
3. Аналогично откройте чистую 01: она строит модель, таблицы и рисунки.
   02 обучает демонстрационную сеть и сравнивает прогнозы; 03 проверяет алгоритм
   и связку с сетью. Выполняйте 00→01→02→03. Если в новом runtime отсутствуют
   зависимости, сначала выполните 00 в этом runtime.
4. Перед каждой ячейкой написано, что получится. В конце есть проверка чисел.
   Ошибка — не нулевой результат: сохраните её текст и верните в основной чат.

Фактически проверено выполнение ipynb через nbconvert на GitHub runner.
Личный веб-интерфейс Colab не проверен; его скорость зависит от выделенного
runtime, загрузки и установки пакетов. Фактические времена — notebook-times.json.

## Изменить параметр
В 01 есть ползунки датчиков, Fog, буфера и доли мобильных датчиков. Они выполняют
новый запуск, не меняют эталон v2. Другой способ: скопировать ячейку с
`simulate(Config(...))` и изменить один параметр. Число событий и интенсивность
не одно и то же. Меняя их, следите за долей потерь и длиной окна наблюдения.
Не переносите новый результат в статью без перегенерации таблиц и реестра.

## Понять результат
Базовые400/ч — общий поток: очереди могут отсутствовать. Ноль ожидания не ошибка.
Стресс1200/с — отдельный искусственный режим, не реальный поток парковки.
p95 — характеристика выборки, не гарантия доставки. MAE и покрытие оценивают
разные свойства: лучшая MAE сети не означает правильный хвост распределения.
P и B имеют разные первые критерии; P может быть медленнее. Такие исходы сохранены.

## Локальный запуск для технической проверки
```
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
cd v2/code && python -m unittest discover -s tests -v
```
Для полного воспроизведения из чистого checkout (нужен LaTeX):
`python scripts/build_artifacts.py`. Команда удаляет и заново создаёт только
генерируемые `results/`, `colab/`, `article/figures/`; свои несохранённые файлы
не помещайте в эти каталоги. Исходники и v2 остаются нетронутыми.
